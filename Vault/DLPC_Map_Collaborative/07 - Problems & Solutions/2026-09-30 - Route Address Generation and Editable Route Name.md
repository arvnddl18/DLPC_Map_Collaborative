# Problem & Solution: Route Address Auto-Generation & Editable Route Name

## Date
2026-09-30

## Context
In the collaborative map UI, users define road-aligned routes between start and end coordinates using OSRM routing and reverse geocoding via OSM Nominatim.

## Problem
1. **Wrong / Stale Addresses on Route Generation**: When the user modified start/end coordinates (either by typing into input fields or picking points on the map) and clicked "⚡ Generate Road Route", the start and end addresses did not automatically update. Stale addresses (often default initial coordinates like Apollo/Dragon Compound) remained in the read-only and editable address inputs and were saved to the backend database.
2. **Non-Editable Route Name**: The route name/identifier was hardcoded to an autogenerated ID (e.g. `ROUTE-7M5CR`), without an input field or persistence schema for a user-specified custom route name.

## Root Causes
1. **Missing Geocoding in Route Calculation**: The `#btn-calc-route` click listener only invoked `routeEngine.calculateRoadRoute()`, without calling `lookupAddress()` for the updated start and end coordinates.
2. **Address Input Overwrite Lockout**: `lookupAddress()` skipped updating the editable address if `corrEl.value` was already set, meaning initial default addresses were never replaced on new coordinate selection.
3. **No Input Change Listeners**: Manual edits to latitude and longitude input textboxes had no `change` or `blur` event listeners to trigger reverse geocoding.
4. **Lack of Route Name Schema & UI**: Neither the UI inspector panel nor the payload schema supported an editable `name` property.

## Solutions Implemented
1. **Concurrent Route Calculation & Reverse Geocoding**:
   - In `app.js` (`#btn-calc-route`), concurrently executed road alignment calculation and reverse geocoding:
     ```javascript
     const [res] = await Promise.all([
       routeEngine.calculateRoadRoute(sLat, sLng, eLat, eLng),
       this.lookupAddress('start', sLat, sLng, true),
       this.lookupAddress('end', eLat, eLng, true)
     ]);
     ```
   - Enhanced `lookupAddress(type, lat, lng, forceUpdateEditable)` to set loading status and update both generated and editable address fields when forced or when not manually modified by the user.
   - Added manual coordinate change listeners (`#route-start-lat`, `#route-start-lng`, etc.) and explicit `🔄 Auto-lookup` buttons for one-click re-generation.
2. **Editable Route Name**:
   - Added a dedicated "Route Name" form input with real-time panel title synchronization.
   - Persisted `name` across backend APIs (`server.js`, `Code.js`), database (`database.json`), and collaborative broadcast events.
   - Updated map layer tooltip in `routing.js` to prominently display custom route names.
   - Integrated route name matching in global search (`executeSearch`) and related route indicators in the NAP inspector.
3. **Synchronization**:
   - Rebuilt Google Apps Script bundle with `npm run build:gas`.
   - Verified functionality end-to-end with Playwright browser tests.
